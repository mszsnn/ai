

### Q25：Beam Search 为什么累计 log probability？为什么需要长度惩罚？

序列概率是多个条件概率连乘，容易数值下溢；取 log 后乘法变成加法。由于 log probability 通常为负，长句累计分数天然更低，所以项目用 `score / length^0.7` 缓解对短句的偏好。

### Q26：当前推理实现最大的性能问题是什么？

每个时间步、每条 Beam 都重新调用完整模型，导致 Encoder 被重复计算，Decoder 历史前缀也被重复计算。应只编码源句一次、将 beams 合成 Batch，并缓存 Decoder Self-Attention 的历史 K/V 和 Cross-Attention 的 K/V。

### Q27：Attention 的时间和空间复杂度是多少？

Self-Attention 核心计算约为 `O(B·L²·D)`，注意力矩阵内存约为 `O(B·H·L²)`；Cross-Attention 约为 `O(B·T·S·D)`。长序列的二次复杂度是主要瓶颈。

### Q28：当前项目的数据规模和模型配置是什么？

共有 10000 对句子，按 8000/1000/1000 划分。中文/英文词表分别为 8227/7181；`d_model=512`、8 头、FFN=1024、3 层 Encoder、3 层 Decoder、Dropout=0.1、Batch Size=32、Adam 学习率 `1e-4`，估算参数量约 2735 万。

### Q29：这个项目最值得讲的优点和最需要承认的不足是什么？

优点是完整手写了数据、Teacher Forcing、Attention、三类 Mask、Encoder–Decoder、Checkpoint 和两种搜索解码，且能解释张量 Shape。不足是缺少正式评估与自动测试，词级 Tokenizer OOV 较高，包导入和依赖配置不规范，Checkpoint 没保存词表/配置，训练可复现性和推理性能仍不够。

### Q30：如果继续优化，你会按什么顺序做？

第一步补齐可运行性和评估：统一包结构、依赖、随机种子、自动测试、验证循环、best checkpoint、BLEU/chrF。第二步提升质量：清洗对齐数据、改用 SentencePiece/BPE、调小模型或扩大数据、加入 Warmup、Label Smoothing、梯度裁剪和 Early Stopping。第三步优化性能：动态 Padding、混合精度、Encoder/KV Cache、批量 Beam Search 和高效 Attention。

## 5. 针对当前代码的深挖追问

### 5.1 面试官可能让你现场解释的代码

1. `BasicTokenizer.encode_target`：为什么 SOS 只在输入，EOS 只在标签。
2. `Transformer.make_decoder_mask`：两个不同 Shape 的 Mask 如何广播并组合。
3. `MultiHeadAttention.forward`：拆头和合头前后的 Shape。
4. `handler_attention`：为什么 Mask 在 Softmax 前，为什么除以 `sqrt(d_k)`。
5. `DecoderBlock.forward`：三大子层的执行顺序及 Cross-Attention Q/K/V 来源。
6. `train_one_epoch`：梯度清零、反向传播和更新顺序。
7. `beam_search_translate_sentence`：为什么用 log probability，如何保留 Top-K，长度惩罚如何比较。

### 5.2 当前实现的优点

- 训练/验证/测试划分使用固定随机种子。
- 只用训练集构建词表，避免明显数据泄漏。
- 中英文 Tokenizer 分离，特殊 Token ID 明确。
- Teacher Forcing 的输入/标签错位正确。
- 三类 Mask 的语义和广播方向基本正确。
- Cross-Attention 正确使用 Decoder 状态作为 Q、Encoder 输出作为 K/V。
- Loss 忽略 PAD。
- 推理使用 `eval()` 和 `no_grad()`。
- Beam Search 使用 log probability、完成候选池和长度惩罚。
- Checkpoint 同时保存模型和 Optimizer 状态，可继续训练。

## 6. 进阶题与参考思路（5 道）

### 进阶 Q1：怎样用自动测试证明 Decoder 没有“偷看未来”？

固定模型为评估模式，构造两条目标序列，使它们在位置 0 到 t 完全相同、t 之后不同；分别 Forward 后，断言位置 0 到 t 的 logits 在误差范围内一致。如果结果受未来 Token 影响，说明 Causal Mask 的方向、Shape 或广播有问题。还应直接断言上三角 Mask 为 True、主对角线及下三角为 False。

### 进阶 Q2：训练 Loss 突然变成 NaN，你会如何系统排查？

先定位首次出现 NaN 的 Batch 和层，检查输入 ID、长度、Loss、梯度范数及各层激活；重点检查学习率过大、梯度爆炸、整行 Attention 全被 Mask、混合精度下 `-1e9` 溢出和非法数据。然后用单 Batch、关闭 Dropout、降低学习率、梯度裁剪和异常检测逐步缩小范围，不能只通过重启训练掩盖问题。

### 进阶 Q3：如果数据从 1 万对扩展到 1 亿对，系统架构要怎样调整？

语料改为分片和流式读取，预先训练并版本化 SentencePiece，离线完成质量过滤、去重和按文档分组划分；训练侧使用 IterableDataset、Token 数动态 Batch、分布式采样、混合精度、多 GPU DDP、周期性可恢复 Checkpoint，并记录数据分片游标。评估要按领域和长度分桶，保证测试集去重且不进入词表或训练。

### 进阶 Q4：如何把当前 Beam Search 改造成低延迟在线翻译服务？

请求层按总 Token 数动态组 Batch；每个源句只运行一次 Encoder；把 Beam 维并入 Batch，一次计算全部候选；缓存每层 Decoder Self-Attention K/V 和 Cross-Attention K/V；加入最大长度、超时、提前停止和候选重排。服务侧监控 P95/P99 延迟、EOS 到达率、输入截断、GPU 利用率和输出重复，并将模型、配置、双语 Tokenizer 打成同一版本制品。

### 进阶 Q5：怎样设计实验，证明某个优化真的有效？

先确定唯一变量和主要指标，例如“BPE 是否改善 OOV 句翻译”：固定数据划分、模型容量、训练预算和随机种子，仅替换 Tokenizer；至少运行多个随机种子，比较总体 BLEU/chrF、含 OOV 句子分组指标、序列长度、参数量和推理延迟；保存显著性分析与好坏案例。只有验证集选择完成后，才能在测试集做一次最终报告。

## 8. 最后速记

面试前至少保证能脱口而出：

1. Attention 公式与 `sqrt(d_k)` 的原因。
2. Encoder、Decoder、Cross-Attention 的 Q/K/V 来源。
3. 三类 Mask 的 Shape、True/False 语义与广播方式。
4. Teacher Forcing 的输入/标签错位。
5. logits 为什么不先 Softmax 就进 CrossEntropyLoss。
6. Greedy 与 Beam Search 的差异，log probability 和长度惩罚。
7. 当前真实数据规模、词表规模、模型配置和参数量。
8. 当前版本至少 5 个明确不足及对应改法。
9. 为什么当前代码是 Post-LN，而不是注释所说的 Pre-LN。
10. 为什么不能只靠训练 Loss 宣称翻译效果好。

最稳妥的面试表达是：先讲当前真实实现，再讲发现的问题，最后讲可验证的改进方案。能准确解释限制，通常比把项目包装成“生产级系统”更有说服力。
